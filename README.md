# 🛡 115RiskGuard

**Индивидуальный риск-контроль по 115-ФЗ для физических лиц.**

Локальный инструмент, который по вашей банковской выписке оценивает вероятность
блокировки / приостановки счёта или карты по 115-ФЗ — *до* того, как это
увидит антифрод банка — и даёт конкретный план, что поправить прямо сейчас.

- Полностью локальная обработка — ни один файл никуда не отправляется.
- Мультибанковский парсер: Сбер, Тинькофф, Альфа-Банк, ВТБ, Газпромбанк
  + универсальный режим и поддержка PDF.
- Гибридная модель риска: rule-based движок (на базе МР ЦБ 4/16/17/18/19,
  положений 375-П и 519-П, 161-ФЗ и реальных кейсов banki.ru 2025–2026)
  плюс опциональная CatBoost-модель.
- Красивый Streamlit-дашборд + экспорт отчёта в PDF и Excel.
- What-if симулятор: «а что если я сделаю ещё 40 P2P за месяц?».
- Локальная история анализов в SQLite + режим еженедельного мониторинга.
- «Режим максимальной защиты» — самые консервативные пороги.

> ⚖️ Это не юридическая консультация и не официальная позиция ЦБ. Итоговое
> решение принимает банк. Мы подсвечиваем паттерны, из-за которых массово
> блокировали счета в 2025–2026, и объясняем, как их устранить.

## Быстрый старт

```bash
git clone https://github.com/asabiru/115riskguard.git
cd 115riskguard

python -m venv .venv
source .venv/bin/activate           # Windows:  .venv\Scripts\activate
pip install -r requirements.txt

# (опционально) сгенерировать демо-выписки
python sample_data/generate_samples.py

streamlit run app.py
```

Открываем `http://localhost:8501`, загружаем CSV/XLSX/PDF выписки — всё считается
локально.

Требуется **Python 3.11+**.

## Telegram-бот

Весь движок доступен и как Telegram-бот (aiogram 3). Бот работает
в режиме long-polling, поэтому публичный домен не нужен — запускаете
прямо у себя на машине.

```bash
# 1) получите токен у @BotFather (команда /newbot)
export TELEGRAM_BOT_TOKEN="123456:AA..."

# 2) установите зависимости и запустите
pip install -r requirements.txt
python -m riskguard.bot
# или после pip install -e .:
riskguard-bot
```

В боте всё кликабельное — inline-кнопки, ничего набирать руками
не нужно:

* «📥 Загрузить выписку» — прислать CSV/XLSX/PDF как документ
* «📊 Последний анализ» — сводка + топ-3 флага
* «📝 Все флаги» — полный список с объяснениями и планом действий
* «🧪 What-if» — накладываем сценарии («+20 P2P», «+10 крипто», «+30% наличных»,
  «+300 000 ₽ поступления», «Сбросить»)
* «📚 История» — последние 10 анализов из SQLite, клик — детали
* «🛡 Защита: Стандарт / Макс» — одним нажатием ужимает пороги на 25 %
* «📄 PDF» / «📊 Excel» — отдают полный отчёт прямо в чат

История пишется в `data/history.db` (можно переопределить через
`RISKGUARD_DB`). Лимит файла — 15 МБ.

## Как подготовить выписку

### 🟢 Сбербанк

1. [СберБанк Онлайн](https://online.sberbank.ru) → вкладка **«История операций»**.
2. Укажите период → **«Экспорт»** → **CSV** или **Excel**.
3. Загрузите полученный файл в приложение. Формат: кодировка UTF-8,
   разделитель `,` или `;`.

### 🟡 Тинькофф / Т-Банк

1. [Tinkoff.ru](https://www.tinkoff.ru/mybank/) → **«Счета и карты»** →
   нужная карта/счёт → **«Выписка»**.
2. Диапазон дат → **«Скачать CSV»**. Разделитель `;`, кодировка UTF-8.

### 🟡 Альфа-Банк

1. [Альфа-Клик / Альфа-Онлайн](https://online.alfabank.ru/) → **«История»** →
   **«Экспорт»**.
2. Выбор формата — **XLSX** (рекомендуется) или **CSV**.

### 🟣 ВТБ

1. [ВТБ-Онлайн](https://online.vtb.ru) → **«История операций»**.
2. **«Выписка»** → период → **XLSX**.

### ⚪ Газпромбанк

1. [Газпромбанк-Онлайн](https://online.gazprombank.ru) → **«История»** →
   **«Выписка»** → **Excel**.

### 🟤 Универсальный режим

Любой CSV/XLSX с колонками «дата», «сумма» (подписанная или разделённая
на «приход/расход»), «описание». Парсер поймёт их автоматически.

### 📄 PDF-выписки

Поддерживается `.pdf`, если это текстовый PDF (не сканы). Под капотом —
`pdfplumber`. Сканы нужно сначала распознать OCR-ом (например,
[Tesseract](https://github.com/tesseract-ocr/tesseract)).

## Как устроена оценка риска

1. **Парсинг** (`parser.py`) приводит выписку любого банка к канонической
   схеме: `date`, `amount` (signed), `channel`, `counterparty`, ...
2. **Признаки** (`feature_engineering.py`) — ~30 агрегированных метрик:
   - частота и объём P2P (день / 7д / 30д, уникальные контрагенты);
   - транзит и mule-поведение (остаток на конец дня, same-day turnover);
   - крупные необъяснимые поступления;
   - наличные, крипта/обменники, букмекеры;
   - скрытая предпринимательская деятельность;
   - всплески оборота, «новые» контрагенты, ночные операции и т.д.
3. **Правила** (`risk_engine.py`) — каждое правило срабатывает в двух
   зонах: жёлтой (0.5 от веса) и красной (1.0). Для каждого флага генерится
   пояснение «почему это опасно», ссылка на нормативку и конкретный
   action-hint (что делать прямо сейчас).
4. **Итог** — `rule_score` (0..100), `probability` (сигмоид), уровень
   🟢 / 🟡 / 🔴, блендинг с ML-вероятностью (если модель подключена).

Все пороги настраиваются из UI и через `constants.Thresholds`. «Режим
максимальной защиты» — более консервативный набор порогов.

## ML-модель (опционально)

```python
from riskguard.ml_model import RiskMLModel, synthetic_training_dataset

model = RiskMLModel()
X, y = synthetic_training_dataset()
model.fit(X, y)
model.save("data/riskguard.cbm")
```

В Streamlit-приложении загрузка модели произойдёт автоматически, если она
лежит по пути `data/riskguard.cbm`. Блендинг с rule-based скорингом —
`ml_alpha=0.4` по умолчанию.

Синтетический генератор в комплекте — это *учебные* данные. На проде
замените на собственную размеченную историю блокировок.
